# Third-party source references

The proximity polling in `src/game/original-proximity.ts`, shared by the linked-bridge, sliding-stone, weighted-lift, gate, fan, checkpoint and passive-hinge adapters, adapts the behavior of `TT_Toolbox_RT/Behaviors/ScaleableProximity.cpp` from [doyaGu/CKBuildingBlocks](https://github.com/doyaGu/CKBuildingBlocks/tree/fca1963e39e64daa480918661732b1b0e45fe7b8), revision `fca1963e39e64daa480918661732b1b0e45fe7b8`, licensed under Apache-2.0. The upstream file credits Terratools/Virtools. The adaptation is written in TypeScript, uses Three.js vectors, implements the recovered range transitions and adaptive countdown, and samples script frames at presentation cadence in the native path (fixed physics ticks in the Rapier path). Fan attenuation in `src/game/original-fan.ts` also adapts `TT_Gravity_RT/Behaviors/ProximityVolumeControl.cpp` from that revision: local-frame squared distance and exponential gain, applied to browser audio. The upstream license is included in [public/licenses/CKBuildingBlocks-Apache-2.0.txt](public/licenses/CKBuildingBlocks-Apache-2.0.txt) and copied into the production output.

The local NMO importer uses the separately installed LibCmo21 library; its revision and setup are documented in [original-import.md](docs/original-import.md). Original Ballance game assets are user-supplied, staged separately by the deploy command and have separate rights from these source references.

The Hermite curve evaluation in `src/game/original-ufo-animation.ts` adapts `CK2dCurve::GetY` from [doyaGu/CK2](https://github.com/doyaGu/CK2/tree/122a5c896fb2d56d239063ba17d595b73de470de), revision `122a5c896fb2d56d239063ba17d595b73de470de`, under Apache-2.0. The TypeScript adaptation handles the saved UFO curves and their authored tangents; it is not a general curve editor. The license is included in [public/licenses/CK2-Apache-2.0.txt](public/licenses/CK2-Apache-2.0.txt). The claw's quaternion tangents were recovered separately from the supplied `CK2_3D.dll`; the simplified TCB tangent implementation in the public rendering-engine reconstruction is not used. The ending camera's null-parent and self-relative-position behavior is informed by `3DTrans/Behaviors/SetParent.cpp` and `SetPosition.cpp` in the CKBuildingBlocks revision cited above.

The native inertia probe links against a separately installed [IVP SDK reference](https://github.com/doyaGu/ivp/tree/7579664996e68040dd0158081b04f612e6a2d515). Its source remains separately installed. The repository includes numerical measurements, source-mesh hashes, and the project's own probe wrapper. The reference functions, conversion, verification and limitations are documented in [original-inertia.md](docs/original-inertia.md).

The [IVP WebAssembly simulation bridge](docs/original-ivp-wasm.md) links that same separately supplied SDK and now supplies the default gameplay solver in development and production builds. The repository contains the project's bridge, build and verification scripts. The production build packages the generated ES loader and WASM under a content-hashed asset directory; SDK source, native executables and compatibility headers remain local. This is a build of the referenced SDK reconstruction, not execution of the original Ballance DLL.

The `OriginalForce` controller and spring setup in `scripts/ivp-simulation-bridge.cpp` adapt `physics_RT/Behaviors/PhysicsForce.cpp` and `SetPhysicsSpring.cpp` from the same Apache-2.0 CKBuildingBlocks revision cited above. They preserve captured world-direction impulses per PSI, the core-space application-point shortcut, and absolute bidirectional spring settings. The bridge adds numeric validation and explicit handle ownership; no original executable is run.

`src/game/original-ivp-contact.ts` adapts `PhysicsContact.cpp` and `Behaviors/PhysicsContinuousContact.cpp` from the same Apache-2.0 CKBuildingBlocks revision. It preserves per-group friction counts, delayed activation/deactivation, pending-record retention, and output ordering, while receiving numeric body/contact IDs from the project bridge.

`src/game/original-box.ts` adapts `include/VxOBB.h` and the scalar `OBBOBBCore` in `src/VxIntersect_BoxBox.cpp` from [doyaGu/VxMath](https://github.com/doyaGu/VxMath/tree/20625db68420ad1f443573d54b09bacfb8f78fa1), revision `20625db68420ad1f443573d54b09bacfb8f78fa1`, under Apache-2.0. The TypeScript adaptation retains normalized matrix axes (including authored slight shear), direct projection onto both boxes' axes, and the nine cross-axis tests. It uses JavaScript double arithmetic, so original float-boundary equivalence remains unverified. The upstream license is included in [public/licenses/VxMath-Apache-2.0.txt](public/licenses/VxMath-Apache-2.0.txt).

`src/game/original-ivp-sound.ts` adapts the collision-speed thresholds, per-ID cooldown and normalized impact level from `physics_RT/Behaviors/PhysicsCollisionDetection.cpp`, and displacement-based rolling speed from `TT_Gravity_RT/Behaviors/SpeedOMeter.cpp`, in the same Apache-2.0 CKBuildingBlocks revision. It maps the recovered Sound.nmo graph and object attribute IDs to browser audio commands; original audio files remain separately supplied assets.

`src/game/original-music.ts` maps the recovered music graphs to explicit browser playback state, informed by `Logics/Behaviors/BinaryMemory.cpp` and `Sounds/Behaviors/WavePlay.cpp` from the same Apache-2.0 CKBuildingBlocks revision. It uses browser media completion, script-time delays and separately supplied recordings; the implementation and remaining differences are documented in [original-music.md](docs/original-music.md).

The script-frame clamping in `src/game/original-script-clock.ts` follows `CKTimeManager::PreProcess` in the CK2 revision cited above, checked against the supplied CK2.dll. Its limits come from the supplied Menu.nmo. Native swing/sack sequencing in `original-ivp-runtime.ts` adapts the float32 Delayer accumulation in `Logics/Behaviors/TimerMini.cpp` from the CKBuildingBlocks revision cited above. See [original-frame-timing.md](docs/original-frame-timing.md) for arithmetic evidence and remaining differences.

The normal camera in `src/game/original-camera.ts` adapts the time-based progression and relative orientation behavior of `Logics/Behaviors/BezierProgression.cpp` and `3DTrans/Behaviors/SetEulerOrientation.cpp` from the Apache-2.0 CKBuildingBlocks revision cited above. It uses the same CK2 curve evaluator and the separately recovered dynamic-position arithmetic. Original rig matrices and navigation parameters are extracted from the user-supplied assets; scope and validation are documented in [original-camera.md](docs/original-camera.md).

Idle satellite orbit axes and rate in `original-point-trails.ts` follow `TT_Gravity_RT/Behaviors/Extra.cpp` in the Apache-2.0 CKBuildingBlocks revision cited above. The bounded trail sampler follows the stationary emission and interpolation behavior in `TT_ParticleSystems_RT/ParticleEmitter.cpp` and `TimePointEmitter.cpp`; it uses Three.js points and source-extracted lifetime, color and size settings, rather than the original particle runtime. See [collectible effects](docs/original-effects.md).

`original-point-extra.ts` additionally adapts TT Extra's activation, scatter and pursuit equations, cached timestep coefficient, squared hit test and next-frame ready signal from the same `Extra.cpp` source. Browser scoring and cancellation are integrated with the recovered P_Extra_Point.nmo graph. The original hit-burst particle systems and a full scheduler are not implemented by this adapter.

`original-death.ts` follows `Logics/Behaviors/GroupIterator.cpp`, `Collision/Behaviors/BoxBoxIntersection.cpp`, and `Collision/CKCollisionManager_AdvancedIntersectionFunctions.cpp` from the Apache-2.0 CKBuildingBlocks revision cited above, using the existing VxMath-derived oriented-box helper. Ordered volume membership and frame delays come from the supplied Gameplay.nmo. See [authored player death volumes](docs/original-death.md).
